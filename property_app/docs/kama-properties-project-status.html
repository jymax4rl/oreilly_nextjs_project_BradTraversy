2. Completed capabilities (current advancement)

2.1 Cloudinary media (major milestone)

Status: operational in production. Cloudinary is configured and used for property images and audio. Legacy local files under public/properties/ were backfilled; MongoDB stores secure_url and publicId per asset.
  • Folder layout: kama-properties/hosts/{hostId}/properties/{propertyId}/images (and /audio)
  • Backfill: npm run db:backfill-cloudinary-folders — 37/37 seed listings migrated
  • Provision: npm run db:provision-cloudinary-folders
  • Audit: npm run db:audit-property-images
  • New listings: browser uploads directly to Cloudinary (signed upload); Vercel only saves JSON metadata — avoids 4.5MB body limits and supports multiple photos
  • Display: galleries, cards, emails, and booking flows resolve URLs from MongoDB

2.2 Host listing creation

  • Multi-step add-property form with per-field validation and step blocking
  • Mobile-friendly photo picker (camera + gallery); optional client-side resize fallback
  • Guest contact: default from host profile (username, account email, onboarding phone); optional per-listing email/phone override
  • Carousel layout fix for last wizard step; media PATCH API fix for Next.js 16 async params

2.3 Bookings, calendar & payments

  • Property availability API and host calendar UI
  • Guest bookings with rates (nightly / weekly / monthly)
  • Guest modify / cancel bookings with versioned updates and lifecycle emails
  • Flutterwave payment initialize + webhook; transaction → booking flow
  • Admin: host approval, transactions, manual booking creation

2.4 Host & guest experience

  • Host onboarding application and verified-host gate for listings
  • Messaging between guest and host on property threads
  • Saved properties, my bookings, host listings dashboard
  • Multi-currency display context; branded confirmation emails

3. Architecture: how new listing photos work

StepWhat happens
1Host submits listing JSON → POST /api/properties creates property + signed Cloudinary upload params
2Browser uploads each file to api.cloudinary.com (not through Vercel)
3PATCH /api/properties/{id}/media saves image URLs and folder metadata in MongoDB
4Redirect to live property page on www.isisel.com

Why this matters: the earlier “migration” moved storage to Cloudinary; this flow removes Vercel as a file proxy so multiple full-size phone photos work reliably.
